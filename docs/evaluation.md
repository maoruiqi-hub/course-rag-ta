# 评测记录

## 1. 目的

验证两件事：

1. 检索能否把问题对应的课件页找回来（Hit@K）；
2. 生成答案是否依据资料、引用是否和来源卡片一致（人工抽查）。

评测资料为仓库内自建的 `data/samples/demo_langchain.pptx`（6 张幻灯片），
不包含任何第三方课件，结果可由 `scripts/evaluate.py` 复现。

## 2. 环境

| 项目 | 配置 |
|---|---|
| Python | 3.12.12 |
| LangChain | 1.4.7 |
| 对话模型 | DeepSeek `deepseek-flash`，关闭 thinking |
| Embedding | 本地 FastEmbed `BAAI/bge-small-zh-v1.5`（512 维） |
| 向量库 | Chroma 1.5.9，cosine |
| 切分 | `chunk_size=500`，`chunk_overlap=50` |
| 检索 | Top-K = 5 |

运行：

```powershell
python scripts\evaluate.py
```

换成长课件后，Top-K 命中率通常会下降。

## 4. 答案抽查

使用 `KnowledgeBase.search(k=5)` 检索，再把上下文交给 `deepseek-flash` 生成答案。
以下为人工检查记录：

| 问题 | 检索来源 | 生成耗时 | 结论 |
|---|---|---|---|
| RAG 的两个核心组件是什么？ | 第 2 张幻灯片、第 1 页、第 1–50 行、第 4 张幻灯片 | 2.0s | 正确；索引 + 检索与生成，引用与来源一致 |
| stuff 和 map-reduce 有什么区别？ | 第 4 张幻灯片、章节：文本总结、第 1–50 行、第 2 张幻灯片 | 1.5s | 正确；处理方式和适用场景都说清楚了 |
| Agent 有哪三个工具？ | 第 1–50 行、第 2 张幻灯片、第 6 张幻灯片、第 4 页 | 1.2s | 正确；知识库检索、计算器、当前时间 |

延迟为单次问答（不含首次模型下载和索引），受网络和模型负载影响会有波动。

## 5. 已知问题

- 示例 PDF 是英文内容，PDF 页引用正常，但中文 PDF 的文本抽取质量取决于原文件字体；
- 演示 PPTX 只有 6 页，检索难度低；第 7 章课件有 76 页，Top-K 需要适当调大；
- 摘要中的页码标记由模型生成，可能出错；问答页的来源卡片由程序生成，更可靠；
- 评测没有做 LLM-as-judge 或人工双盲评分，只做了小样本抽查，结论仅用于课程作业。
