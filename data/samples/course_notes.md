# LangChain 与课程资料问答：复习笔记

> 这是一份为本项目演示而写的自建课程笔记，不包含任何第三方课件内容。
> 上传后可以向它提问，回答会标注行号。

## 1. 为什么要做 RAG

大语言模型有两个典型限制：

1. **知识滞后**：训练数据有截止时间，无法回答最新事件。
2. **幻觉**：模型可能生成看起来合理、但资料中没有依据的内容。

RAG（Retrieval-Augmented Generation，检索增强生成）的思路是：先从外部资料中检索与问题相关的片段，再把片段和问题一起交给模型生成答案。这样既能补充知识，又能让答案回到原文核对。

## 2. RAG 的两个核心组件

一个典型的 RAG 应用包含两个主要组件。

### 2.1 索引

索引通常离线进行，包括三个步骤：

- **加载**：用 Document Loader 读取 PDF、Word、PPT 等资料；
- **拆分**：用文本拆分器把长文档切成较小的 chunk；
- **存储**：用 Embedding 模型把 chunk 转成向量，写入 VectorStore。

### 2.2 检索与生成

- **检索**：根据用户问题，用 Retriever 从向量库中找出最相关的 chunk；
- **生成**：把问题和检索到的 chunk 一起放入提示词，交给 ChatModel 生成答案。

## 3. 文本总结的两种策略

### 3.1 stuff

把文档的全部内容一次性放入提示词。优点是实现简单、信息完整；缺点是受模型上下文窗口限制，长文档成本高。

### 3.2 map-reduce

先把文档分批，每批生成一个局部摘要（map），再把局部摘要合并成最终摘要（reduce）。适合长文档，但调用次数更多。

选择策略时可以根据字符数、token 数和成本综合判断，而不是只看模型是否支持长上下文。

## 4. 文档切分

常用的切分器是 `RecursiveCharacterTextSplitter`。它按分隔符逐级尝试：

1. 先按空行切；
2. 再按换行切；
3. 再按中文句号、分号、逗号切；
4. 最后才按字符切。

课程项目可以使用 `chunk_size=500`、`chunk_overlap=50`。chunk 太小会丢失上下文，太大会降低检索精度并增加 token 消耗。

## 5. 引用与页码

问答系统要让人相信答案，最好满足两点：

1. **答案有依据**：提示词要求模型只根据检索资料回答；
2. **来源可核对**：程序把检索结果的文件名、页码、原文摘录展示出来。

页码信息应该在文档加载阶段写入 metadata，而不是让模型自己编。PDF 可以按页加载，PPTX 可以按幻灯片加载；Word 没有稳定页码，可以引用章节和段落。

## 6. 多轮对话

多轮问答需要处理追问。例如用户先问“RAG 是什么”，再问“它有什么缺点”。第二个问题如果直接拿去检索，可能缺少“RAG”这个关键词。

一种简单做法是用一次轻量 LLM 调用把追问改写成独立问题，再拿改写后的问题去检索。改写失败时回退到原问题，保证主流程不中断。

## 7. Agent 与工具调用

Agent 的核心是“模型 + 工具 + 循环”：

- 模型判断是否需要调用工具；
- 工具执行后把结果返回给模型；
- 模型根据结果决定继续调用工具还是给出最终答案。

课程资料助教可以挂三个工具：知识库检索、计算器、当前时间。工具调用轨迹要展示给用户，方便解释 Agent 的行为。

## 8. 工程化检查清单

- API key 放在 `.env`，不要提交到 Git；
- 文档上传要做文件名清理和大小限制；
- 检索失败、API 超时、余额不足都要有中文提示；
- 单元测试不要依赖真实 API；
- README 写清楚架构、运行步骤、已知限制和参考项目。

## 9. 常见问题

**Q：为什么回答里没有引用？**
A：可能是检索没有命中，或者模型没有按提示词输出编号。先检查来源卡片，再调整 chunk 大小和 Top-K。

**Q：为什么 PPT 的页码不对？**
A：页码来自加载阶段；如果解析器把多页合并成一个 Document，页码就会丢失。需要按页/按幻灯片生成 Document。

**Q：Word 为什么没有页码？**
A：Word 的分页是排版结果，不是文档结构。更可靠的做法是引用章节和段落序号。

## 10. 小结

课程资料智能助教把文档解析、文本切分、向量检索、提示词工程和流式界面串成一条完整链路。它的价值不只是“能回答问题”，而是让答案可追溯、可评估、可维护。
